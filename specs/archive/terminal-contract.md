## Goal

Once linger gives a child a PTY, linger remains that child's terminal for the
whole session. For every complete query in the documented owned profile, child
progress and the reply stream are independent of whether zero, one, or many
presentation clients are attached. Bytes outside the owned grammar remain exact
presentation passthrough; linger makes no client-independence guarantee for
replies generated by attached terminals to unowned/vendor queries.

Complete anchor A1 at the same boundary: every live-reachable VT grid is
renderable, and restore recreates its cells and pens exactly.

## Definition of done

All of the following hold together:

1. A pure, bounded terminal transducer owns the profile table below, removes
   complete owned queries from presentation output, and emits exactly the
   table-prescribed zero or one reply independently of the client roster.
2. Its VT projection is exactly the existing `Vt.feed`. Every input byte not
   belonging to a complete owned query—including an incomplete final prefix—is
   emitted exactly once and in order; ordinary ANSI and kitty/sixel/APC/DCS
   payloads remain byte-for-byte passthrough.
3. An application-neutral PTY probe progresses before any client attaches and
   receives the same single reply with zero, one, or two clients. Interactive
   fish is a regression case, never an implementation branch.
4. The child sees a stable compatibility profile selected by linger, not the
   launcher's terminal: `TERM=xterm-256color`, `TERM_PROGRAM=linger`,
   `TERM_PROGRAM_VERSION=0.1.0`.
5. The inherited grid-fidelity target lands: `restore_grid`,
   `restore_grid_reachable`, and `resume_grid` are green; all former fuzzer
   exclusions are exercised and pass.
6. `./lake build Theorems Tests` and `./tests/e2e.sh` are warning-free and green;
   each new theorem/test has been break-verified and recorded in
   `SCRATCHPAD.md`; a fresh reviewer finds no correctness blocker.

Review/revise cap: two fresh-review rounds. An unchanged blocker after round 2
forces a re-plan rather than another cosmetic pass.

## Normative virtual-terminal profile

Byte notation: `ESC=0x1b`, `CSI=ESC [`, `OSC=ESC ]`, `DCS=ESC P`, and
`ST=ESC \\`. Decimal parameters are ASCII without leading zeroes. CSI buffering
is capped at 128 bytes, OSC at 256, and an owned DCS candidate at 2048.
Implementation and tests are derived from this table; implementation constants
are not the normative source.

| family | complete request grammar | sampled state | exact reply | unsupported / notes |
|---|---|---|---|---|
| DA1 | `CSI c`, `CSI 0 c` | none | `CSI ? 1 ; 2 c` | other parameter forms are unowned |
| DA2 | `CSI > c`, `CSI > 0 c` | none | `CSI > 0 ; 0 ; 0 c` | other parameter forms are unowned |
| DSR status | `CSI 5 n`, `CSI ? 5 n` | none | `CSI 0 n`, respectively `CSI ? 0 n` | — |
| CPR | `CSI 6 n`, `CSI ? 6 n` | cursor, origin, top | `CSI row ; col R`, respectively `CSI ? row ; col R` | `col=x+1`; `row=y+1` with DECOM off, else `1` when `y<top`, otherwise `y-top+1` |
| XTVERSION | `CSI > q`, `CSI > 0 q` | none | `DCS > | linger 0.1.0 ST` | — |
| text area | `CSI 18 t` | rows, cols | `CSI 8 ; rows ; cols t` | pixel/window queries are unowned |
| default fg | `OSC 10 ; ? BEL|ST` | fixed palette | `OSC 10 ; rgb:ffff/ffff/ffff ST` | input terminator does not alter reply terminator |
| default bg | `OSC 11 ; ? BEL|ST` | fixed palette | `OSC 11 ; rgb:0000/0000/0000 ST` | — |
| cursor colour | `OSC 12 ; ? BEL|ST` | fixed palette | `OSC 12 ; rgb:ffff/ffff/ffff ST` | — |
| XTGETTCAP | `DCS + q payload ST` | none | `DCS 0 + r payload ST` | all keys explicitly unsupported; payload echoed exactly |
| DECRQSS | `DCS $ q payload ST` | none | `DCS 0 $ r ST` | all selectors explicitly unsupported |
| kitty keyboard | `CSI ? u` | none | no reply | consumed; no kitty-keyboard capability is claimed; DA1 terminates startup probing |

A byte sequence not matched by a complete row is unowned and passthrough. The
XTGETTCAP and DECRQSS rows are the only DCS exceptions. An over-cap candidate
becomes unowned passthrough rather than growing memory.

## Pure contract

```text
Terminal.feed   : Vt -> Scan -> List UInt8 -> Result
Terminal.finish : Scan -> List UInt8 × Scan
Result          : Vt × Scan × visible-bytes × ordered-replies
```

For a fixed starting VT, scanner, and child byte stream, `Result.vt`, scanner,
and replies are independent of `Session.clients`. A complete recognized query
is either owned (absent from `visible`, table-prescribed reply) or unowned
(present in `visible`, no linger reply), never both. Reports such as OSC 7/133
still reach `Vt`; ordinary output remains presentation data.

`finish` returns an incomplete pending prefix unchanged with a reset scanner,
emits no reply, and does not feed those bytes again (they already reached `Vt`).
On PTY EOF/child exit, Session broadcasts the returned bytes before exited and
close effects.

The corrected VT projection treats private `CSI ? u` as state-neutral. The
current parser's unconditional final-`u` DECRC is a bug: only non-private
`CSI u` restores cursor/pen. Step 1 fixes and gates that distinction before
using `Vt.feed` as the projection oracle.

## Reachability and replay contract

`LiveReachableVt` is the least predicate containing `Vt.init`, closed under
`Vt.feed`, `Vt.resize`, and `Vt.quiesce` (the VT projection of checkpoint
save/load). `renderable_of_liveReachable` discharges the shape hypothesis.
`Session.run` gets a trace lift showing its VT remains live-reachable.
Fidelity is not claimed for an arbitrary foreign/corrupt decoded checkpoint;
checkpoint exactness composes only from a live-reachable source.

## Out of scope / non-goals

- Detecting fish, vim, shells, or any child program.
- A complete xterm/VT520 implementation or arbitrary vendor-query catalog.
- Translating output separately for heterogeneous attached terminals.
- Advertising kitty keyboard or graphics capability through the virtual
  profile. Explicit graphics bytes still pass through while attached; image
  persistence remains a settled non-goal.
- Reopening windows, panes, picker, or process-tree restoration decisions.
